## Project Purpose

This project is exploring a two-component two-dimensional Coulomb plasma / vortex gas as a Monte Carlo model for BKT-type physics modified by a Majorana-induced interaction. The target problem is described in `lit/BKTMajoranaMonteCarlo.pdf`; the reference phase-diagram paper is `lit/7205_1_online.pdf`; the current working notebook is `full_approx.ipynb`, which imports `Monte_Carlo_sim.py` and `plotting.py`.

The model has neutral charges `zeta_i = +/- 1` in 2D, a hard core, and interaction

```text
V_ij(r) =
  - zeta_i zeta_j K log(r / xi)
  - T log(2 cosh((E0 / T) exp(-r / xiF))).
```

The first term is the standard logarithmic 2D Coulomb gas interaction. The second term is charge-independent and attractive for all particle pairs. The problem statement focuses on the regime:

- `K / T` arbitrary, with a BKT transition expected near the usual Coulomb-gas value when `E0 / T = 0`.
- `E0 / T >> 1`.
- `xiF / xi >> 1`.
- For large `K / T`, opposite charges should form tightly bound pairs.
- For small `K / T`, charges should be more plasma-like / unbound.
- Main physics question: as `E0 / T` is increased, does the BKT transition change character, and do additional phases appear, such as phases where vortex pairs are locked together but proliferate?

## Reference Paper Takeaways

`lit/7205_1_online.pdf` is Orkoulas and Panagiotopoulos, "Phase diagram of the two-dimensional Coulomb gas: A thermodynamic scaling Monte Carlo study", J. Chem. Phys. 104, 7205 (1996).

Key reference points:

- Standard model: hard disks with equal numbers of positive and negative charges and pair potential proportional to `-q_i q_j log(r_ij / sigma)`.
- Reduced parameters: `rho* = rho sigma^2`, `T* = k_B T D / q^2`.
- At zero density, the KT transition starts at `T* = 1/4`, which corresponds to inverse coupling near `K/T = 4` if `K` is mapped to `q^2 / D`.
- The KT line shifts to lower `T*` at finite density.
- The reference estimates the vapor-liquid critical point at roughly `T*_c = 0.056`, `rho*_c = 0.21`.
- Their coexistence table spans approximately `T* = 0.035` to `0.055`.
- They identify the transition using the dielectric response. The inverse dielectric curve is compared to the universal KT jump criterion, effectively the line `1 / epsilon_0 = 4 T*`.
- Their precision methodology is much more advanced than the current code: thermodynamic scaling Monte Carlo, Ewald treatment for the 2D ion-ion interaction, cluster moves, density/temperature coverage, and finite-size comparisons with `N = 50` and `N = 200`.

## Current Monte Carlo Implementation

`Monte_Carlo_sim.py` implements:

- Periodic square box with minimum-image distances.
- Random rejection initialization with hard-core radius `a`.
- Local single-particle Metropolis moves.
- Hard-core rejection by returning infinite local energy when `r < a`.
- `local_energy_1` / `total_energy_1`:
  `-K q_i q_j log(r / xi)`.
- `local_energy_2` / `total_energy_2`:
  `-T log(2 cosh((E0 / T) exp(-r / xiF)))`, implemented stably as `-T * np.logaddexp(x, -x)`.
- `local_energy_full` / `total_energy_full`: sum of first and second terms.
- Observable traces: total energy and mean nearest opposite-charge distance.
- Return values: `snapshots`, `E_trace`, `pair_trace`, and acceptance rate.

The latest notebook uses:

```text

L = 200
N_plus = 20
N_minus = 20
a = 1.0
xi = 1.0
xiF = 5.0
T = 1.0
kappa = 1.0
e0_red = 5.0
K = kappa * T
E0 = e0_red * T
step_size = 0.6
n_sweeps = 5000
sample_every = 50
seed = 0
```

The recorded output is:

## Simulation-Code Review Findings

Conclusion: the main latest-notebook convention bug has been fixed. `Monte_Carlo_sim.py` uses physical energies and accepts with `exp(-dE / T)`, while `full_approx.ipynb` now converts reduced controls to physical inputs before calling it. The remaining risk is that older first-term-only files use the reduced-energy convention directly, so the project still has two valid but different conventions in different files.

### Formula Implementation

The project interaction is

```text
V_ij(r) =
  - zeta_i zeta_j K log(r / xi)
  - T log(2 cosh((E0 / T) exp(-r / xiF))).
```

`Monte_Carlo_sim.py` implements this physical-energy version correctly in shape:

- Coulomb/log term: `local_energy_1` and `total_energy_1` use `-K * qi * qj * log(r / xi)`.
- Majorana/second term: `local_energy_2` and `total_energy_2` use `x = (E0 / T) * exp(-r / xiF)` and `-T * logaddexp(x, -x)`, which equals `-T log(2 cosh(x))`.
- Full term: `local_energy_full` and `total_energy_full` add these two parts.

So the code is formula-consistent if interpreted as physical `V`, not reduced `beta V`.

The equivalent reduced-energy form would be

```text
beta V_ij(r) =
  - kappa zeta_i zeta_j log(r / xi)
  - log(2 cosh(e0_red exp(-r / xiF))),

where kappa = K / T and e0_red = E0 / T.
```

In that reduced convention the Metropolis acceptance should use `exp(-delta_beta_V)`, not `exp(-dE / T)`.

### K, T, E0, Beta Consistency

The latest notebook now uses the physical-energy convention correctly:

```text
T = 1.0
kappa = 1.0      # K / T
e0_red = 5.0     # E0 / T
K = kappa * T
E0 = e0_red * T
```

This preserves the intended reduced controls even if `T` is changed:

```text
effective kappa = K / T = kappa
effective e0_red = E0 / T = e0_red
```

This is the correct handoff for the current `Monte_Carlo_sim.py` design. If the engine is later rewritten to compute reduced energies directly, then it should instead accept `kappa` and `e0_red` directly and use `exp(-dE)` for Metropolis acceptance.

`first_term_sim.py` and `BKT_metropolis_organized.ipynb` still use the reduced first-term convention: the input called `K` or `K_over_T` is really `K / T`, and acceptance uses `exp(-dE)`. That is internally consistent for the first-term-only reduced model. It is inconsistent with `Monte_Carlo_sim.py` if both are interpreted as taking the same kind of `K`.

### Metropolis Acceptance

The correct acceptance rule depends on what `dE` means:

- If `dE = Delta V` is a physical energy, use `min(1, exp(-dE / T))`.
- If `dE = Delta(beta V)` is already dimensionless, use `min(1, exp(-dE))`.

Current files:

- `Monte_Carlo_sim.py`: uses physical-energy formulas and `exp(-dE / T)`. This is correct only under the physical convention.
- `first_term_sim.py`: uses a reduced first-term formula and `exp(-dE)`. This is correct only under the reduced convention.
- `BKT_metropolis_organized.ipynb`: uses `K_over_T` and `exp(-dE)`. This is consistent for reduced first-term exploration.
- `full_approx.ipynb`: labels parameters as reduced (`kappa`, `e0_red`) and now converts them to physical `K` and `E0` before calling the physical-energy engine. This is currently consistent.

### Other Simulation Risks

- `full_approx.ipynb` currently sets `target_term = "second"`, so it is not sampling the full project interaction. The recorded run is a second-term-only all-pairs attraction problem, not the BKT-plus-Majorana problem.
- The second term is charge-independent. In second-only or full runs it can cluster same-charge and opposite-charge particles alike. The current `nearest_unlike_distance` observable can miss same-charge clustering and cannot distinguish candidate locked-pair or proliferated-pair phases.
- The code uses minimum-image distances for a logarithmic long-range interaction. This is useful for exploration but is not the same as the periodic 2D Coulomb/Ewald treatment used in the reference paper.
- `a` and `xi` are separate. The project expansion is around the core scale `xi`; current notebooks use `a = xi = 1`, which is consistent, but future parameter scans should preserve or explicitly justify any difference.
- The previous plot-title ambiguity has been fixed: `plotting.py` now displays the caller-provided label/value, and `full_approx.ipynb` passes `E0/T` for second-term runs and `K/T` for first/full runs.

## Important Constraints And Gaps

- Parameter semantics are currently inconsistent across files:
  - `first_term_sim.py` treats the first-term energy as dimensionless `beta U` and accepts with `exp(-dE)`.
  - `Monte_Carlo_sim.py` treats energies as physical energies and accepts with `exp(-dE / T)`.
  - `full_approx.ipynb` now bridges this correctly for the physical-energy engine by setting `K = kappa * T` and `E0 = e0_red * T`.
- The latest notebook is configured for the second term only. It is not yet sampling the full interaction unless `target_term` is changed to `"full"`.
- The long-range logarithmic interaction is approximated by minimum-image periodic distance. The reference paper uses Ewald treatment / careful boundary handling. Current results should not be used for precision phase boundaries.
- The code is canonical fixed-`N` local Metropolis. It does not implement thermodynamic scaling MC, grand-canonical pair insertion/deletion, NPT moves, or density-changing moves.
- No dielectric observable is implemented. The reference phase diagram relies on inverse dielectric response and the KT universal jump criterion.
- No finite-size scaling is implemented.
- No heat capacity, susceptibility, Binder cumulant, free-energy curve, or coexistence construction is implemented.
- No cluster or pair moves are implemented. This matters in strongly bound regimes, especially for `E0 / T >> 1`.
- `initialize_positions` in `Monte_Carlo_sim.py` has no maximum-attempt guard, so it can hang at high density or large hard-core radius.
- The second term is charge-independent and attractive for all pairs. This may drive dense clustering until stopped by the hard core. That appears consistent with the extracted project equation, but it should be rechecked against the physical derivation before interpreting new phases.
- Current observable `nearest_unlike_distance` is useful for opposite-charge pairing but cannot distinguish all possible clustered or locked-pair phases by itself.
- Plotting labels for `full_approx.ipynb` are now parameterized by `display_label` and `display_value`, so this specific ambiguity is fixed.
- `README.md` is stale relative to the actual file names and current full/second-term code.
